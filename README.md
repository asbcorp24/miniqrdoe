# MiniQRDOE — журнал маршрутных карт

Мобильное приложение PHP 8.1+ / SQLite. Учёт операций изготовления деталей, станков, работников, групп и отчётов. Все файлы сайта размещены локально — нет CDN, Composer и внешних библиотек.

## Установка
1. Включить PHP-модуль pdo_sqlite.
2. Дать PHP права записи в каталог var/ (создаётся при первом запросе).
3. Настроить DocumentRoot виртуального сайта на каталог public/ — это самый безопасный вариант. Если корень сайта совпадает с корнем репозитория, включить mod_rewrite и AllowOverride All для корневого .htaccess.
4. Открыть сайт. Таблицы SQLite создаются автоматически.
5. В справочниках создать работников и станки: цифровые QR-коды создаются автоматически. Распечатать этикетки. Создать группы деталей.
6. Использовать HTTPS на телефоне, иначе доступ к камере запрещён.

Локальный запуск: php -S localhost:8080 -t public (требуется pdo_sqlite).

## Сценарий
Сотрудник сканирует QR станка, QR работника, выбирает группу и нажимает «Начал работу». Сервер назначает уникальный номер детали и время начала (UTC). После «Закончил» сервер записывает окончание, длительность и увеличивает количество готовых деталей. Когда изготовлены все детали, группа закрывается. Операции атомарны, используется SQLite BEGIN IMMEDIATE.

Группа хранит время приёма, плановый срок изготовления, количество, число готовых деталей и фактическое время закрытия. Один рабочий не может вести две активные операции одновременно. Номера деталей не переиспользуются.

## Аналитика
Фильтр по датам; число операций, готовых деталей, активных работ, суммарная длительность, показатели по работникам и станкам, распределение по дням, CSV-экспорт для Excel.

## Ограничения первой версии
- Нет встроенной аутентификации и ролей. **Не размещайте приложение в открытом интернете без защиты VPN или HTTP-аутентификации на сервере.** QR-код не является подтверждением личности.
- QR-сканер использует встроенный BarcodeDetector браузера, который есть не везде. При несовместимости — ручной выбор. Для полной поддержки мобильных браузеров нужна локально размещённая JS/WASM-библиотека декодирования.
- Нет интерфейса коррекции брака, отмены, резервных копий, печати QR, сложных KPI и аудита изменений.
- Временные метки сохраняются в UTC. До промышленной эксплуатации необходимо проверить интерфейс и базу на целевом сервере и телефонах.

## USB-сканер QR (режим HID Keyboard)

Подключите 2D USB-сканер к компьютеру: система должна видеть его как клавиатуру. Настройте на сканере суффикс **Enter**. Язык клавиатуры не важен, потому что коды содержат **только цифры**. На странице «Работа» сканируйте, не выбирая поле ввода:

- `100000000001` — станок (тип `1` и 11 цифр идентификатора).
- `200000000001` — работник (тип `2` и 11 цифр идентификатора).
- `300000000001` — группа деталей с ID **1** (тип `3` и 11-значный ID).

После каждого считывания значение автоматически подставляется в соответствующий список. Порядок сканирования любой. Сканер распознаётся по быстрой последовательности символов и Enter; обычный набор текста остаётся доступным. Если курсор стоит внутри поля ввода, переключитесь на свободную область страницы, чтобы не перенаправлять ручной ввод. USB-сканер не требует HTTPS или доступа к камере.

## Печать QR-этикеток

Откройте пункт **«QR-этикетки»** в верхнем меню (страница `public/labels.php`). Выберите станки, работников или группы, отметьте нужные наклейки и нажмите **«Печать выбранных»**. Доступны макеты 60×40 мм и 70×50 мм на A4. Коды состоят из 12 цифр: станок начинается на `1`, работник — на `2`, группа — на `3`. В этикетке также печатаются тип и название.

QR-коды генерируются **в браузере без сети** из локального файла `public/assets/qrcode.min.js` (QRCode.js, MIT, лицензия: `public/assets/QRCode-LICENSE.txt`). Для аппаратного сканирования задайте USB HID и суффикс Enter. Сканер не зависит от русской или английской раскладки клавиатуры. Для печати без искажений установите масштаб 100%, отключите колонтитулы браузера и выберите правильный тип бумаги.

## Apache: размещение в подкаталоге /qrq/

Если файлы проекта находятся в каталоге сайта `/qrq/`, открывайте `http://server/qrq/`. Корневой `.htaccess` на Apache 2.4+ перенаправляет внутренние запросы `/qrq/assets/style.css`, `/qrq/assets/app.js` и `/qrq/labels.php` в папку `public/` без повторного переписывания. Убедитесь, что установлены `mod_rewrite` и `AllowOverride All` для каталога проекта. Если сайт размещён непосредственно с DocumentRoot `public/`, корневой `.htaccess` не требуется.

Если в консоли браузера возникла ошибка MIME `text/html` для CSS или 404 для JS, откройте напрямую `http://server/qrq/assets/style.css`: сервер должен вернуть именно CSS (Content-Type: text/css), а `http://server/qrq/assets/app.js` — JavaScript. Если вместо этого открывается HTML главной страницы или 404, сначала проверьте применение `.htaccess`, физический путь `public/assets/`, настройки виртуального хоста и правила родительского каталога. Не меняйте MIME-тип CSS вручную, когда сервер фактически возвращает HTML.

## Админка с паролем

Для первого запуска установите пароль **на сервере** через командную строку в корне проекта:

```bash
php tools/set_admin_password.php
```

Введите пароль длиной минимум 12 символов. Он сохраняется в виде PHP-хеша в `var/admin_password.hash` (не в Git; недоступен из веб-каталога). Если PHP не имеет доступа на запись в `var/`, выдайте необходимые права процессу, запускающему CLI, и PHP. Для смены пароля повторно запустите ту же команду; все действующие админ-сессии автоматически сбросятся.

Вход — пункт **«Админка»** или `/login.php`. Рабочий журнал, запуск и завершение операций остаются доступны без админского пароля. Создание групп, редактирование справочников, отчёты, выгрузка CSV и печать QR-этикеток требуют входа администратора. После пяти неудачных попыток в одной сессии вход блокируется на 15 минут. Кнопка «Выход» завершает админ-сессию.

**Без заданного файла пароля админка закрыта.** Не используйте пароль через незащищённое HTTP-подключение: для доступа вне полностью доверенной локальной сети настройте HTTPS. Админский пароль не заменяет учётных записей рабочих — их операции пока привязываются к QR/выбору работника.

## Автоматические QR-коды

При добавлении станка или работника администратор вводит **только название/ФИО**. PHP самостоятельно создаёт уникальный **12-значный цифровой код** с криптографически случайной 11-значной частью: `1XXXXXXXXXXX` для станка и `2XXXXXXXXXXX` для работника. Код хранится в SQLite. Для группы код `3` + ID группы, дополненный нулями до 11 знаков (например, `300000000001`). При первом открытии обновлённой версии ранее сохранённые буквенные коды станков и работников автоматически заменяются цифровыми, при этом записи и история операций сохраняются. **Старые QR-этикетки перестанут работать — распечатайте новые.** Латинская раскладка для USB-сканера больше не нужна. Наклейки доступны на странице QR-этикеток.
